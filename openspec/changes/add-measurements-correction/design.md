# Design

## Context

Этап 2 готов: справочники приборов с калибровочными параметрами, партии со стартовыми параметрами (сырое показание + ogSg + correctedBrix в `startParams`), настройки `correctionFormula`, IPC-фабрика, Repository-паттерн. Реализуем `measurement-correction` (8) и `measurements` (9) из базовой спеки.

## Goals / Non-Goals

**Goals:**
- Конвейер «сырое показание → прибор → формулы → скорректированный SG» с полным следом в записи замера — сердце ценности продукта.
- Ввод замера за ≤3 действия с дефолтами из последнего замера.
- Все коррекции — чистые функции в `shared/`, покрытые юнит-тестами без Electron.

**Non-Goals:**
- Единый журнал (таймлайн замеров+операций) — этап 4 `batch-journal`; здесь история правок хранится (аудит) и видна в карточке замера.
- График плотности и расчёты ABV/сахара/прогноза — этап 4 (`density-chart`, `fermentation-calculations`).
- Отчёты, экспорт замеров.
- Автоматическая температура (термометр не моделируется отдельным прибором — температура вводится в поле замера).

## Decisions

### D1. Модель данных: одна таблица замеров + аудит ревизий

- `measurements`: `id`, `batchId` FK CASCADE, `kind` (`density | temperature | ph`), `instrumentId` FK SET NULL (обязателен по zod для density), `rawValue` REAL, `unit` (`sg | brix` — только для density), `tempC` REAL nullable (температура сусла в момент замера), `correctedSg` REAL nullable (каноническое значение для всех расчётов), `corrections` JSON (массив шагов `{type, input, output, note}` — полный след), `measuredAtUtc`, `notes` nullable, `createdAtUtc`, `updatedAtUtc`.
- `measurement_revisions`: `id`, `measurementId` FK CASCADE, `action` (`update | delete`), `snapshot` JSON (снимок записи до правки), `revisedAtUtc`. Требование 6.1.6 (правки не портят график навсегда).
- Инвариант: для density `correctedSg` всегда вычисляется при сохранении (как OG в этапе 2) — «только скорректированные значения» (2.10) обеспечивается на уровне данных, не дисциплины чтения.

### D2. Формулы коррекции (чистые функции, `shared/calculations/correction.ts`)

- **Ареометр, температура** — формула из vision «Корректировка показаний ареометра АС-3», дословно: `SG_corr = S × (1 + 3.7e-4 × (T − T_кал))`, где S — сырое показание (если введено в Brix — сначала `brixToSg`), `T_кал` — **калибровочная температура конкретного ареометра** (новое поле прибора, по умолчанию 20 °C; у старых моделей бывает 15/17.5 °C — требование vision). Тесты — по формуле: при S=1.050: 20 °C → без поправки, 25 °C → 1.0519, 30 °C → 1.0539, 15 °C → 1.0481. Зоны: рабочая 15–30 °C (ошибка ≤0.001 SG); при T <10 или >35 °C — предупреждение (вне аппроксимации), требование vision.
- **Рефрактометр, до брожения**: Brix × WCF → `brixToSg` (уже есть).
- **Рефрактометр, брожение (точная)**: кубическая формула Террилла дословно из vision, Bi = correctedBrix партии (из startParams; если старт в SG — инверсия), Bf = текущий corrected Brix.
- **Рефрактометр, брожение (линейная)**: соотношение Баллинга: `RE = 0.1808·Bi + 0.8192·Bf` (в °Plato), SG из Plato той же сахарной формулой. Широко распространённая линейная альтернатива Терриллу; выбор формулы — из настроек (`correctionFormula`, этап 2).
- **Инверсия SG→Brix**: численное решение (бисекция по монотонной `brixToSg`) — нужно для Bi при старте в SG и для калибровочной пары.
- **Калибровочная пара**: `WCF_personal = invertBrixToSg(SG_ареометра) / Brix_рефрактометра`; пара (обе точки + время) и вычисленный WCF записываются в карточку рефрактометра (`instruments.calibrationPair` JSON — новая колонка, миграция 0002).

### D3. Пайплайн при сохранении замера плотности (BatchMeasurementService / функция)

Вход: `{rawValue, unit, instrumentId, tempC?, kind}` + прибор + настройки формулы + startParams партии. Выход: `correctedSg` + `corrections[]`:
1. density + ареометр: если введено в Brix — `brixToSg` (требование vision: S берётся после перевода Brix → SG); темп-коррекция по `T_кал` прибора (если tempC задана; предупреждение при T <10/>35 °C) → калибровочное смещение → `correctedSg`.
2. density + рефрактометр (Brix): WCF → `correctedBrix`. Партия бродит (есть Bi и замер после постановки): Террилл/линейная → SG; иначе (первый замер = старт) → `brixToSg`.
3. temperature/ph: сохраняются как есть, `correctedSg` = null.
Каждый шаг дописывает запись в `corrections[]` с входом/выходом — требование 2.7 (полный след).

### D4. IPC: каналы замеров и калибровки

`measurements:list-by-batch {batchId}`, `measurements:create`, `measurements:update {id, patch}`, `measurements:delete {id}`, `measurements:revisions {id}`, `instruments:calibrate {instrumentId, refrBrix, hydrometerSg}` → `{instrument}` (персональный WCF + пара). Каналы через ту же фабрику/конвенции. `settings:get` уже даёт формулу — сервер читает её при создании замера (единый источник истины, а не доверие renderer'у).

### D5. UI: быстрый ввод ≤3 действий и пакетный ввод

- В списке активных партий — кнопка «Замер» на строке партии (действие 1). Диалог ввода: фокус в поле показания (действие 2 — набор значения), Enter сохраняет (действие 3). Дефолты: прибор/единицы/температура из последнего замера партии, формула из настроек (6.1.4). Диалог остаётся открытым после сохранения (6.1.7) — следующий замер = действие 2+3.
- Динамическая форма (6.1.2): kind density показывает выбор прибора (обязателен) + единицы + температуру (обязательна только для ареометра) + предпросмотр correctedSg (6.1.3, через ту же функцию resolve-пайплайна в shared — мгновенно, до сохранения); kind temperature/ph — только значение и время.
- Правка замера: та же форма, при сохранении снапшот уходит в ревизии; карточка замера показывает ревизии и след коррекции (2.7). Удаление — диалог подтверждения, снапшот в ревизии с action=delete.
- Предупреждение об усреднённой коррекции (6.3.5): если рефрактометр без калибровочной пары (wcf не персональный) — баннер у результата в диалоге и в карточке замера.

## Risks / Trade-offs

- [Таблица проверки в vision не сходится с формулой в строках 5/15/25 °C] → нормативна формула `S × (1 + 3.7e-4·(T−T_кал))`; тесты пишутся по ней (расхождение с таблицей доложено пользователю). Если таблица авторитетнее — правка одной чистой функции после уточнения.
- [Bi отсутствует, если партия ставилась в SG] → инверсия `invertBrixToSg(ogSg)` — численно точно (бисекция до 1e-9).
- [Террилл даёт бессмысленный SG вне своего диапазона] → zod-диапазоны входа (Brix 0–80, SG 0.9–1.2) + предпросмотр в форме; крайние значения видны до сохранения.
- [Кнопка «Замер» на каждой строке скрывает путь ≤3 действий для партии не из списка] → для партии из карточки путь тоже ≤3 (кнопка в карточке → значение → Enter).
- [Ревизии растут] → удаляются каскадно с замером; объём мал (ручные замеры).

## Migration Plan

Миграция 0002: две новые таблицы + колонка `calibrationPair` у приборов; штатное применение при старте с бэкапом (скелет). Обратной совместимости с данными нет (не выпущено).

## Open Questions

- Порог «партия бродит» для применения Террилла: сейчас — замер после даты постановки и наличие Bi. На практике первый замер рефрактометром на бродящем суле при потере correctedBrix (SG-старт) — уже покрыт инверсией. Уточнится на реальном сезоне.
