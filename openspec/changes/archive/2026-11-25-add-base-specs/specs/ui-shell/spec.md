# Spec Delta

## Purpose

Сквозные требования к оболочке интерфейса: темы, клавиатурное управление, масштабирование, доступность, корректные пустые и загрузочные состояния, сохранение состояния представления.

## ADDED Requirements

### Requirement: Светлая и тёмная темы
Система ДОЛЖНА (SHALL) поддерживать светлую и тёмную темы интерфейса.

#### Scenario: Переключение темы
- **WHEN** пользователь переключает тему со светлой на тёмную
- **THEN** интерфейс полностью перерисовывается в тёмной теме без перезапуска приложения

### Requirement: Клавиатурное управление
Система ДОЛЖНА (SHALL) позволять выполнять все основные действия — создание замера, переключение партий — с клавиатуры.

#### Scenario: Создание замера с клавиатуры
- **WHEN** пользователь добавляет замер плотности, не используя мышь
- **THEN** весь путь от выбора партии до сохранения замера выполняется с клавиатуры

### Requirement: Корректное масштабирование
Система ДОЛЖНА (SHALL) корректно масштабироваться при изменении масштаба системных настроек на 100, 125 и 150 %.

#### Scenario: Масштаб 150 %
- **WHEN** в системных настройках установлен масштаб 150 %
- **THEN** элементы интерфейса пропорционально масштабируются без обрезания текста и наложения элементов

### Requirement: Контраст текста
Система ДОЛЖНА (SHALL) соблюдать минимальные требования контраста текста WCAG AA.

#### Scenario: Проверка контраста
- **WHEN** текстовые элементы проверяются на контрастность в светлой и тёмной темах
- **THEN** все они соответствуют уровню AA

### Requirement: Осмысленные пустые состояния
Система ДОЛЖНА (SHALL) отображать пустые состояния с подсказкой первого действия вместо пустой таблицы или списка.

#### Scenario: Первый запуск
- **WHEN** пользователь открывает приложение, в котором ещё нет ни одной партии
- **THEN** вместо пустого списка показывается подсказка «Поставьте первую партию» с действием создания

### Requirement: Индикация длительных операций
Система ДОЛЖНА (SHALL) показывать состояние загрузки длительных операций (генерация отчёта, пакетный пересчёт) с индикацией прогресса.

#### Scenario: Пакетный пересчёт
- **WHEN** выполняется пакетный пересчёт по многим замерам
- **THEN** интерфейс показывает прогресс операции и не выглядит зависшим

### Requirement: Сохранение состояния представления
Система ДОЛЖНА (SHALL) сохранять состояние представления (сортировку списка партий, открытую вкладку) между сеансами работы.

#### Scenario: Перезапуск приложения
- **WHEN** пользователь сортирует список партий по дате постановки и перезапускает приложение
- **THEN** список остаётся отсортированным по дате постановки, а последняя вкладка — открытой
