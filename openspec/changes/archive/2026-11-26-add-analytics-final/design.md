# Design

## Context

Этапы 1–3 готовы: каркас, справочники/настройки/партии, замеры с полным конвейером коррекции (correctedSg каноничен, след и ревизии сохраняются). Финальный этап добавляет осмысление данных: расчёты, график, журнал, экспорт, справку. Реализует `fermentation-calculations` (8), `density-chart` (3), `batch-journal` (3), `data-portability` (2), `glossary` (3).

## Goals / Non-Goals

**Goals:**
- Замкнуть цикл: поставил партию → меришь с коррекцией → видишь динамику, расчёты и прогноз → архивируешь → экспортируешь и повторяешь в следующем сезоне.
- Все новые числовые функции — чистые, с тестами на контрольных примерах.
- Без новых runtime-зависимостей: график — собственный SVG.

**Non-Goals:**
- Сравнение партий на одном графике, PDF-отчёты, многоязычность, импорт CSV — «отложено» из vision.
- Продвинутые модели прогноза (нелинейная ферментация, машинное обучение) — простая линейная регрессия с честным диапазоном.
- Печать/стили экспорта «для людей» — JSON для данных, не для просмотра.

## Decisions

### D1. Аналитика: `shared/calculations/analysis.ts` (чистые функции)

- **ABV (Hall, дословно из vision)**: `ABV = (76.08 × (OG − FG) / (1.775 − OG)) × (FG / 0.794)` в % об. Контрольный пример для теста: OG=1.092, FG=0.998 → ≈ 12.3 % об. (по формуле).
- **Видимая степень сбраживания**: `AAS = (OG − FG) / (OG − 1) × 100 %`.
- **Остаточный сахар**: экстракт по Баллингу `RE = 0.1808·OE + 0.8192·AE` (OE/AE в °Plato — через `invertBrixToSg`), `RS г/л = RE × FG × 10` (1 °P ≈ 1 г/100 г раствора).
- **Прогноз завершения (диапазон)**: по последним замерам плотности (correctedSg) линейная регрессия. Вход: ≥3 точек, разброс по времени ≥48 ч. Два наклона: по всему окну и по последним трём точкам → два ETA достижения целевой плотности (target: константа `FORECAST_TARGET_SG = 0.999` — «сухое», константа этапа, в UI показывается). Диапазон = [min(ETA), max(ETA) + 1 сутки]. Наклон ≥ 0 (плотность не падает) → «по текущей динамике завершение не прогнозируется». Точек мало → прогноз не показывается («недостаточно данных» — честно, спека 6.3.6 требует именно диапазон/неопределённость).
- Все результаты считаются ТОЛЬКО из correctedSg (спека 2.10 уже обеспечена уровнем данных).

### D2. Блок «Расчёты» в карточке партии

Карточка: ABV (текущий: OG → последний correctedSg), сбраживание, остаточный сахар, прогноз-диапазон (или причина отсутствия). Под блоком — пометка «Расчёты по скорректированным значениям · формулы: Hall, Баллинг · Подробнее — Справка» со ссылкой-переходом (спека 6.3.4). Форматтеры в `shared/`: `formatAbv(x) → '12.3 % об.'` (без исключений — 6.3.2), `formatDensity(sg, unit)` — при Brix показывает «°Bx (SG)» рядом (6.3.1).

### D3. График плотности — собственный SVG

- Данные: density-замеры партии (correctedSg, время). Ось X — даты, Y — SG (диапазон по данным ± паддинг).
- Маркеры по приборам (6.3.3): круг — ареометр, ромб — рефрактометр, квадрат — иной/без прибора; легенда под графиком.
- Клик/Enter по точке (точки — focusable `<g role="button" tabindex="0">`) открывает существующую карточку замера (6.2.4). Линия соединяет точки по времени.
- Без внешних библиотек: ~150 строк SVG, хватит на все требования спеки.

### D4. Журнал: операции + единый таймлайн

- `batch_operations` (миграция 0003): `id`, `batchId` FK CASCADE, `kind` (`rack | transfer | sugar | acid | nutrient | fining | bottling | other`), `atUtc`, `notes` nullable, `createdAtUtc`. CRUD-репозиторий + IPC по фабрике.
- Таймлайн (клиентская сборка): замеры (тип, значения) + операции (название) + переходы статусов (уже в `batchStatusHistory`) — сортировка по времени, бейджи типов. Отдельные вкладки карточки партии: «Обзор» (карточки, статусы, расчёты, архивация) / «Замеры» (график + диалоги) / «Журнал» (таймлайн + CRUD операций). Заметки — поля замеров и операций (уже есть); в таймлайне показываются.

### D5. Экспорт партии в JSON (data-portability)

- `buildExportPayload(batchId)` в `src/main/export/`: полная сборка — `schemaVersion: 1`, `exportedAtUtc`, `appVersion`, партия (со startParams/finalResult), замеры (с corrections и ревизиями), операции, дрожжи, добавки, история статусов. Чистая функция → юнит-тест.
- `batches:export {id}` → main открывает `dialog.showSaveDialog` (`winemaker-<title>-<date>.json`), пишет файл, возвращает путь или null (отмена). Кнопка «Экспорт JSON…» в карточке партии (только сценарий сохранения файла тестируется вручную; сборка — тестом).
- Автобэкап БД — требование спеки `data-portability` — уже реализовано в скелете (BackupScheduler, ротация 5); в этом change — только приёмочный сценарий.

### D6. Справка: экран «Справка» + подсказки терминов

- Четвёртый таб «Справка» (hotkey Mod+4 в реестре): статьи глоссария (SG, OG, FG, Brix, ATC, WCF, ABV, pH, T_кал, брожение/дображивание) и формулы из vision — Brix→SG, коррекция АС-3 (с рабочей зоной и предупреждением), Террилл, Баллинг, Hall — теми же словами, что реализованы в `shared/calculations` (спека 6.4.3).
- Термины в интерфейсе: компонент `<Term id="og">…</Term>` рендерит подпись с пунктирным подчёркиванием и `title`-подсказкой (наведение — спека 6.4.1); клик ведёт на таб Справка. Применяю к подписям карточки партии и замеров (OG, WCF, ABV, T_кал).

## Risks / Trade-offs

- [Прогноз по линейной регрессии может быть наивен (брожение нелинейно)] → диапазон из двух наклонов + отказ при нехватке данных; пометка в UI «оценка по линейной динамике». Уточнение модели — отдельный change, спека требует лишь «диапазон по динамике».
- [FORECAST_TARGET_SG = 0.999 захардкожен] → честная константа этапа с комментарием; «целевая плотность из партии» — кандидат в полировку (спека не требует конкретного target).
- [Собственный SVG-график — риск кривой вёрстки на масштабах 100/125/150 %] → viewBox + относительные размеры; приёмка масштабов уже в ручном чеклисте пользователя перед релизом.
- [JSON-экспорт раскрывает структуру БД] → это и есть цель (читаемость без приложения); `schemaVersion` задаёт контракт для будущих версий.
- [Таймлайн на клиенте собирается из трёх источников] → единый сортировочный ключ — ISO-UTC строка; объёмы малы (сотни записей).

## Migration Plan

Миграция 0003 (`batch_operations`), штатное применение при старте с бэкапом. Откат не требуется (релизов не было).

## Open Questions

- Целевая плотность прогноза (константа 0.999 vs поле партии) — уточнить на реальном сезоне; спека не фиксирует.
