# Design

## Решения

**Bx-пространство как рабочее для ареометра.** Приборы пользователя показывают только Brix, поэтому любая величина «с прибора» — в °Bx: сырое показание, калибровочная пара, смещение. Канонический SG не меняется (design D7): все переводы в SG — на выходе коррекции, единственный этап — brixToSg.

**Порядок поправок (ареометр):** sg-to-brix (если ввод в SG) → аддитивное смещение °Bx → brixToSg → мультипликативная темп-коррекция на SG. Темп-формула линейна по SG (vision, k = 3.7e-4) и применяется к SG₀ = brixToSg(B_смещённый) — физически коэффициент относится к плотности, а не к сахаристости.

**WCF без инверсии.** Пара в Bx даёт прямое отношение: WCF = гидроBx / рефрBx. Раньше (пара 21,5 °Bx / 1.090 SG) требовался лишний шаг инверсии и точки отказа.

**Инверсия SG→Bx живёт в density.ts.** correction.ts уже импортирует brixToSg из density.ts; перенос invertBrixToSg рядом с прямой формулой убирает потенциальный цикл импортов. Наружу — реэкспорт из correction.ts, все старые импорты работают.

**Миграция 0004 рукописная.** drizzle-kit требует TTY для интерактивного переименования — SQL пишется руками (drop calibration_offset_sg, add calibration_offset_bx), journal и snapshot обновляются вручную с сохранением цепочки тегов 0000–0004. Значения не переносятся: смещений в SG у пользователя не задано (пустые), а «переинтерпретация числа» без пересчёта была бы тихой порчей данных.

## Риски

- Старые партии с ареометровыми замерами в SG: сырые значения остаются в SG, след коррекции честно показывает шаг sg-to-brix — пересчёт истории не требуется (замеры append-only).
- Контрольные точки Новотного не зависят от ареометра (рефрактометр — Bx уже изначально) — не пересчитывались.
