# Proposal

## Why

Сейчас дрожжи в партию можно внести двумя способами: выбором штамма из справочника или рукописным вводом названия. Это нарушает целостность — в базе появляются записи партий без ссылки на штамм (strain_id NULL), которые не обновляются при переименовании и не участвуют в живом отображении. Правило проекта: «есть только один и ровно один способ сделать ЭТО».

## What Changes

- Дрожжи партии — только ссылка на штамм справочника (`strainId` обязателен в контракте). Наименование и производитель из запроса удалены: сервер резолвит их по `strainId` сам и сохраняет снапшот в записи партии (исторический запас на случай удаления штамма).
- Нет нужного штамма в справочнике — пункт «＋ Новый штамм…» открывает модалку быстрого создания; штамм попадает в справочник и сразу выбирается в строку партии.
- Миграция 0005: существующие рукописные записи партий (strain_id NULL) получают штамм в справочнике (если штамма с таким именем ещё нет) и ссылку на него — инвариант восстанавливается на живых данных без потерь.
- Отображение (карточка, журнал) уже резолвит живое имя по ссылке (648e07e); после бэкфилла рукописные записи тоже обновляются при переименовании.

## Capabilities

### New Capabilities

Отсутствуют.

### Modified Capabilities

- `batch-management`: требование «Учёт внесённых дрожжей» — штамм выбирается из справочника или создаётся в нём; ручной ввод наименования исключён.

## Impact

- `src/shared/ipc/contracts.ts` — yeastInputSchema: strainId обязателен, strainName/producer удалены из входа; DTO несёт серверные strainName/producer.
- `src/main/batches/repository.ts` — BatchYeastInput только strainId; резолв штамма в транзакции (create + setYeast), неизвестный strainId → ошибка.
- Миграция 0005 (DML-бэкфилл, рукописный SQL + journal + snapshot).
- `src/renderer/src/ui/composition.tsx` — YeastRowsEditor без полей ручного ввода; NewStrainModal.
- Тесты: резолв имени сервером, отказ на неизвестный strainId, бэкфилл и идемпотентность миграции.
